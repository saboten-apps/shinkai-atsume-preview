## 現在動くもの

React + Vite + TypeScript + Three.js。ガチャ・図鑑・説明・魚詳細・探索を1アプリに統合。URLハッシュで遷移。
日次ガチャは日本時間の日付とSHA-256で全員同じ魚。魚24種の正本は `data/fish.json`。
ガチャと直接2DではThree.jsやGLBを読み込まない。探索3Dは遅延読み込み。
魚は海・川・空に配置され、今日引いた魚だけ近距離で発光。発見後も3D/2Dへ戻れる。景色入りカード生成・共有がある。
図鑑・日次履歴・発見は端末内保存。ガチャ/図鑑のキー `shinkai_gacha_collection_v1` の互換を維持。`hide-v1` と `fish-world-v1` の既存発見記録を壊さない。

3Dは港～駅南口～市役所に加え、千本浜公園周辺・我入道周辺まで連続移動可能。
建物は公式2023年度LOD3の配布セット。56区画、325タイル、建物レコード20,522件、写真あり8,271件。建物データ56,279,560バイト。
LOD3配布セットでも全棟に窓・階段の詳細形状や写真があるわけではない。追加地区の多くは白いモデル。公園の松林は空中写真による表現で、立体の松林は未実装。
追加範囲の2023年度LOD2 211タイルをgml_idで照合し、全てLOD3配布セットに含まれていた。LOD2の追加配信は行っていない。

世界座標はWGS84 ENU: 原点lat35.0815/lon138.8576/h0、x東、y上、zは北の逆。
建物高さは見やすさのため各建物の基部から1.3倍。測量値の補正ではない。
近い区画350mで取得、650mで解放。地面へ着地すると歩行、最高5.5m/s。飛行・上昇・落下・潜水・衝突あり。
飛行範囲x[-1550,1450],z[-2580,1800],y[27.5,420]。
移動先メニュー: 港・駅・市役所・千本浜公園周辺・我入道周辺・近景モデル試作。
千本浜案内点(-738.6,-1220.4)、我入道案内点(205.8,620.6)は概略位置。

道路・植生は2023年度公開データ（詳細収録は主に駅～港の沿線）。地形・水面は2021年度PLATEAU。
海岸の詳細DEMを追加し、地理院の空中写真を投影。写真タイルは近距離最大32枚。
遠景は地理院DEMによる愛鷹山・沼津アルプス・富士山。詳細地形との重複は `regionalLandscape.ts` のシェーダーで除外。

## 建物IDと位置について — 次の実装の重要点

原本のb3dmにはバッチ表の `gml_id` と建物属性、形状座標がある。位置は形状から得られる。
ただし現在の変換では軽量化のため区画・マテリアル単位に統合し、原本の `_BATCHID` と意味的な建物ID対応を描画用GLBに残していない。
**現在のゲームで全建物をタップしてIDを取得できる、という状態ではない。**
`realdata-test/convert-bldg-tex.mjs` と `build-2023-corridor.mjs` が変換の起点。原本は `/tmp/plateau-scratch/source-bldg2023/` にキャッシュ済み。
年度変更でgml_idの継続性は保証されない。施設・店舗用の独立したローカルIDも必要。

最初は一区画で以下を成立させてから全区画に広げる:
1. 原本の建物IDと同じENU座標の位置・範囲・必要な選択用形状を抽出する。
2. 屋根/壁をタップして正しい建物を選択。画面上のUI操作や飛行のドラッグと誤認しない。
3. 選択表示とID・座標の取得。区画を解放・再読込しても同じIDを得られる。
4. 選択用データも近い区画だけ読み、離れたら解放。ガチャに全件を読ませない。
5. 建物と店舗を別エンティティにする。同じビルの複数店舗は入口の座標等で分ける。

実装方法は調査して選ぶこと。GLBのfeature属性を残す方法、建物の平面形状/高さと空間索引を別ファイルにしてray hit座標から特定する方法などが候補。
**gltfpackは頂点・三角形を並べ替えるため、圧縮前のfaceIndexをそのままsidecarへ保存してはならない。** カスタム属性が圧縮・GLTFLoaderを通って残ることも実測で確認。
全建物を個別Meshにして大量のdraw callを増やす案は避ける。
選択の座標/ハイライトは高さ1.3倍と市役所の個別モデル置換にも合わせること。

その後の掲載データ例: 独立したplaceId、buildingId、入口座標、表示名、紹介文、写真、公式サイト/SNS、掲載確認状態。
最初は本人の許可のある1件を管理者が手動登録。未提供の実店舗を協力店として表示しない。
外観写真があるだけで正確な3D形状が自動復元できるとは説明しない。
投稿フォーム・公開前確認・写真加工の許可範囲などは、1件の体験を確認した後に設計する。

## 写真と法的な説明での注意

ユーザーは市役所・びゅうおの写真を撮影済み。元写真16枚は `/workspace/shared/numazu-originals/`（manifest付き）。
共有Drive: https://drive.google.com/drive/folders/1O5tGEX5glvBY5vz1QRgyTubjt7VsjQrM
ZIP添付でGPTが落ちた経緯あり。元写真は取得済みなので再添付を求めない。Driveに追加された写真は必要に応じ取得。
元写真にEXIF/GPSあり。公開用3枚は画素を保ちメタデータを除去済み: `public/environment/city-hall/`。
市役所は写真の一部を反復する外壁、入口、柱、天井と軽量モデルで構成。210mで写真取得、270mで解放。完全な各面写真復元ではない。
びゅうおの個別モデル改修・ユーザー写真の適用は未実装。原本のLOD2/LOD3で形状と写真が同じだった部分を確認済み。年度・LOD更新だけで劇的に改善すると約束しない。

Googleマップのスクリーンショット・航空写真を抽出してテクスチャへ流用しない。公式API利用は別方式で、料金・表示条件・保存制限・沼津の対応範囲の確認が必要。今回は国土地理院とPLATEAU、自前/許可された写真を使う。
建築物の外観利用は日本の著作権法46条の一般的な取扱いを案内済み。「公共施設だから自由」という説明は誤り。民間建築にも適用があり、敷地への立入・施設内撮影・人物・別の美術作品等とは分けて考える。びゅうお固有の商用撮影・3D化の条件を確認済みとは言っていない。
出典表示を維持。提携・公認を装わない。実際の来店記録とバーチャルの探索達成は分ける。
