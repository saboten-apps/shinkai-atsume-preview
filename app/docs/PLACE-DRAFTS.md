# 建物紹介の下書きと公開（2026-11-17）

## 端末で下書きを作る

1. 3Dの建物を約0.5秒長押し。「紹介の下書きを編集（この端末）」を開く。
2. 建物ID・座標が意図した建物か確認し、名前・紹介文・URLを入力する。
3. 写真の公開先パス、撮影者、公開・加工の利用許可、表示クレジットを記録する。
4. 「下書きを保存」で端末に保存。同じ建物を再選択すると復元される。
5. 「保存して書き出す」で保存済みの全下書きをJSONとして保存する。

これは公開権限を持つ管理画面ではない。誰でも自分の端末に下書きを作れるが、アプリ全体を更新する機能はない。
下書きの保存先は専用キー `shinkai_place_drafts_v1`。図鑑などの保存とは独立する。
ブラウザの保存データ削除や別端末へは自動同期しないため、書き出したファイルをバックアップする。
復元はJSONの形式・長さ・ID・座標・URL・画像パスを検証し、競合する既存下書きを自動上書きしない。

写真本体は別途ドライブ等で受け取る。localStorageに画像を保存しない。
公開・加工の同意と、希望するクレジットを確認する。連絡先などの非公開情報を記録欄に入れない。

## ファイルから公開する（開発者が実施）

- 場所IDは原本建物IDとは別。新規下書きではUUIDで作成し、公開後は変更しない。
- 画像を `public/environment/places/任意の名前.webp` 等へ配置。JSONのphotoは `environment/places/任意の名前.webp` とする。
- 元写真・同意の記録・書き出した下書きファイルは公開リポジトリへ追加しない。画像のメタデータ、不要な個人情報・写り込みを確認し、適切に縮小した公開用写真を使う。

正本リポジトリのルートで実行：

```sh
node scripts/import-place-drafts.mjs /path/to/shinkai-place-drafts.json
node scripts/import-place-drafts.mjs /path/to/shinkai-place-drafts.json --apply
npm test
npm run build
```

最初の実行は検査だけ。`--apply` は `src/features/scenery/publishedPlaces.json` を更新する。
建物IDと座標が選択用データと対応すること、画像がpublic配下に実在すること、紹介文・提供者・許可記録・クレジットの入力を確認する。
許可の真偽や画像の権利を自動判定する機能ではない。公開者が内容を確認する。
公開JSONから撮影者の管理用欄と許可記録を除外し、表示用のcreditだけを渡す。
既存の市役所・びゅうおの場所IDを別建物に割り当てることや、公開済みの場所と建物の不整合を拒否する。

新しいデータは長押し紹介・場所一覧・`#/view/場所ID` に反映される。新規の視点は建物の中心から自動生成する。
日本語の名前・紹介文を英語表示でもそのまま表示する（自動翻訳はしない）。
公開後の流れはAI-HANDOFF.mdのpreview同期・検証・PR手順に従う。正本mainへのマージは別途指示が必要。
