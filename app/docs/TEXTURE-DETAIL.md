# 近景の写真と表面の質感（2026-11-15）

## 建物写真

駅周辺の圧縮モデルを作る際に1024pxへ縮小されていた写真のうち、元データに大きい画像が残る63枚を、最大2048pxのWebPとして抽出した。画像を引き伸ばしたものではなく、同じ写真・UVを使用する。港の写真は既に元の解像度を使っているため、この差し替えの対象外。

全ファイルは約13.8MB。3Dを開いた後、実際のカメラから110m以内の建物に対応する画像だけ、最大3枚・同時通信1件で読み込む。160mより離れた画像は元の写真へ戻し、追加テクスチャを解放する。3枚とも2048px正方形の場合、追加GPU容量の目安はミップ込み約64MiB。元のモデル画像は別に保持する。読み込みに失敗した場合も元の写真で探索を続ける。

再生成は `scripts/extract-building-details.py` を使用。元のPLATEAU b3dmキャッシュが必要。manifestには元画像名・サイズ・抽出画像のハッシュを記録している。PLATEAU出典表示は従来どおり残す。

## 表面

壁には弱い色・粗さ・法線の変化、航空写真の地面には弱い色の粒子を加えた。近距離だけの手続き的な質感で、窓や店名、道路標示などを生成するものではない。遠景では細部を消し、追加テクスチャや影の描画回数は増やさない。元写真が不鮮明な建物を精密な実写に復元できるわけではない。

## 歩行

地上のスティック入力に振幅が二重に掛かり、少し倒した際に速度が過度に落ちていたため修正した。半分倒すと約2.75m/s、最大は既存の5.5m/s。坂・衝突・着地・離陸の扱いを保持する。

## 確認

- `npm test`：全40件。入力半分の歩行速度、画像63枚の解像度・ハッシュ・WebP形式を含む。
- `npm run build`：TypeScriptとVite。
- `scripts/check-texture-detail.mjs`：実モデルで高解像度3枚への切り替え、遠方移動による全解放、戻った際の再読込、シェーダーのエラーがないことを確認。
- `scripts/check-walking-brightness.mjs`：実モデルへ着地してスティックで移動・停止・離陸。
- `scripts/check-exploration-3d.mjs`：スマホ幅の探索・発見・2D切替。
- Pixel 10 ProでのFPS・メモリ・近景の見え方は実機確認待ち。負荷が目立つ場合は高解像度の保持数を3→1、次に最大解像度を下げる。ガチャ・2Dでは3Dや追加写真を読み込まない。
