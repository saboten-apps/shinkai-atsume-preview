# 共有探索の試作

## 接続手順

1. Supabaseプロジェクトを用意し、AuthenticationでAnonymous Sign-insを有効化する。
2. SQL Editorで `supabase/shared-exploration.sql` を実行する。既存のポリシーがある場合は内容を確認して統合する。
3. `.env.example` を参考に `.env.local` に公開URLとanon/publishable keyを設定する。service_roleキーは絶対に配信しない。
4. ビルドして配信する。GitHub Actionsでは同じ2変数をビルドステップの環境変数に設定する。
5. 3Dの「一緒に探索」から部屋を作り、招待URLを別端末で開いて参加する。両方で飛行を開始する。

位置・向き・移動状態を10Hzで配信し、受信端末で補間する。図鑑データや移動履歴をDBへ保存しない。認証サービスには匿名ユーザーが作られるため、利用量と削除運用は管理画面で確認する。

招待IDを知る人が参加できる方式。最大3体の他プレイヤーを描画する試作で、サーバーによる厳密な4人定員や不正移動対策は未実装。鬼ごっこの勝敗判定には別途サーバー側判定が必要。

## 検証

別端末2台で入退室、移動・徒歩・潜水、アプリ切替からの復帰、通信断からの復帰を確認する。古い位置は8秒で消える。異なるマップ版の位置は無視する。Pixel 10 Proで単独/2人/4人の30秒FPS・発熱を比較する。実機性能と実サービス接続は接続設定後の確認事項。

## 今回の画面変更

下書き編集・インポート・エクスポートを建物選択から外した。既存の端末内下書きデータは未使用として保持。公開データの管理用インポータは維持。未登録建物には「この場所の情報を募集中」と表示する。

初回ガチャは釣り糸が沈む演出→食いつき→「引き上げる！」→日付固定の魚結果。スキップ可能、動きを減らす設定は即時結果。魚の生息水深を断定する数値は表示しない。潜水服は青・オレンジ、丸いヘルメットとカニ風アンテナに変更。
