# 3Dの描画負荷と実機検証（2026-11-16）

## 今回の変更

- 飛行・視点移動の描画上限を60 FPS、静止した地図を30 FPSにする。水面は時間差分で進める。
- 初期のDPR上限1.5を維持。読み込み中と開始後5秒を除き、2秒窓のFPSが目標の75%未満ならDPRを0.25ずつ下げる（通常下限0.75、低DPR端末は元の値を超えない）。60 FPS目標で55 FPS超が約10秒続けば一段ずつ戻す。
- 非表示ページと写真プレビュー中は描画・シーン更新を休止。表示復帰時は計測と時間差分をリセット。
- 景色モードの目印レイアウト更新を最大10回/秒に制限。探索モードは従来の位置通知周期で更新。
- Reactへの統計通知を5回/秒から1回/秒に削減。2D代替の警告は引き続き約5秒の低FPSで表示。
- 区画ストリーミング範囲、写真テクスチャ、建物形状、事前保存対象は維持。今回は通信量やメッシュ数を減らす変更ではない。

## Pixel 10 Proでの測り方

「まちを見る」から3Dを開く。画面下の「動作情報」を開くとDPR・描画上限・実測FPS・フレーム時間・描画数を確認できる。

1. 港で読み込み表示が消えてから10秒ほど待つ。
2. 「30秒測定する」を押し、その間は視点を動かさずに待つ。完了後「動作情報を保存」でJSONを保存する。
3. 移動先を駅南口にして、読み込み後に同じ測定を行う。
4. 駅前で「飛んでみる」を押し、30秒間移動しながら測定する。
5. 数分飛んだ後も測定し、発熱・操作の引っかかり・解像度の見え方をメモする。

地図の静止中30 FPSは意図した上限。飛行中の目標は30 FPS以上の持続、余裕がある場面では60 FPSまで。移動中のp95が50msを超える状態やDPR下限でも重い状態が続くなら、次段階として描画数・衝突判定・近隣区画の保持量を測り、対象を絞って改善する。
計測中にページが非表示になった場合は結果を破棄して中止。JSONは端末に保存するだけで送信しない。

## 検証と限界

`renderBudget.test.ts` はリフレッシュレートに対する上限、解像度の低下・回復・境界、読み込み除外を確認。
`scripts/check-render-performance.mjs` は変更前後の港、変更後の駅前・飛行、30秒記録のJSON出力、非表示時の描画停止と復帰を確認する。
ブラウザはChromium + SwiftShader（ソフトウェア描画）。PixelのFPSや電池消費・発熱を代用する測定ではない。

動作情報の表示・保存は探索ページの「操作案内・設定」にも共通で搭載。
