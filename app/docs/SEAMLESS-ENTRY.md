# ガチャ結果から3Dへの遷移（2026-11-15）

## 体験

ガチャ結果の先頭に、今日の魚の絵と名前・「今日の魚を探しに行く」を表示する。押すと全画面の待機画面を経て、そのまま3Dの飛行を開始する。途中のモード選択画面と飛行開始操作は不要。ガチャそのもの・日付の固定・抽選・取得記録は従来どおり。

待機画面にも同じ魚を表示し、実際の地形・建物が読み込まれ最初のフレームを描画してから街を表示する。遠方の建物や航空写真は引き続き順次表示する。通信があるため待ち時間そのものをなくす変更ではない。待機中も「結果に戻る」「待たずに2Dで探す」を使える。準備前の3D操作は無効にし、準備が完了すると飛行操作へフォーカスを移す。動きを抑える設定では表示アニメーションを使わない。

結果から直接「軽い2D地図で探す」を選ぶ場合、3Dコード・モデル・航空写真は読み込まない。探索ボタンを押す前の3D先読みも行わない。

## URL・互換

- `#/explore/YYYY-MM-DD`：3Dで直接開始。従来の探索URLも有効。
- `#/explore/YYYY-MM-DD/2d`：2Dで直接開始。
- 魚と隠れ場所は探索へ入った時点の日付を固定。探索前のガチャ記録がないURLは従来同様ガチャへ案内する。
- 発見済みの場合は従来どおり発見カード画面へ。ローカル保存の形式・キーは変更しない。
- 探索中の3D/2D切替では位置を保持。2Dから3Dへ切り替えた場合は俯瞰から再開し、任意で飛行へ進む。
- 3Dの読み込み・描画が失敗した場合は2Dへ。低FPS時の2D案内も保持する。

## 確認

- `npm test`、`npm run build`。
- `scripts/check-exploration-entry.mjs`：3Dコードの通信を遅延させ、待機画面の魚の一致、戻る・2D続行、遅延完了後に3Dが勝手に再表示されないこと、保存データとヘッダー操作の復帰。
- `scripts/check-exploration-3d.mjs`：スマホ幅で1回の操作による自動飛行、UI配置、発見カード、3Dと2Dの切替、WebGL喪失時の2D復帰。
- `scripts/check-exploration.mjs`：直接2Dで発見・カード生成・再読込、コレクション不変、ガチャと2Dで3D通信なし。
- Pixel 10 Proでは、初回通信の待ち時間・操作への移行・戻る操作を確認する。実機の速度はChromiumの自動テストからは判断しない。

## 発見後も街へ戻る（2026-11-15）

発見の有無とカード画面の表示状態を別に管理する。発見画面の「3Dの街に戻る」で自動飛行を再開し、「2Dで街を歩く」でも散策できる。街では「発見カードを見る」からカードへ戻る。同じセッションでは生成済みカードと発見時の景色を保持する。再読み込み後も保存済みの発見画面から街へ戻れ、発見場所付近から再開する。

発見後は探知表示を「発見済み」に切り替え、未発見を示す光るマーカーと再発見操作を出さない。散策しても発見日時・場所・モード・魚の取得記録を上書きしない。保存形式は変更しない。再読み込み後のカード画像は従来どおり再生成する。

`check-exploration-3d.mjs`で、発見→カード生成→飛行再開→同じカード→再読込→飛行再開→2D→カードと記録不変を確認する。`check-exploration.mjs`では、再読込後の2D散策とカード復帰でも3D通信がないことを確認する。選択中の3Dボタンを再度押して待機画面が残る問題も防いだ。
