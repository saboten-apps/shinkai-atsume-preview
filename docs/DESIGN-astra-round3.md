第3弾は、**「全建物の屋根・外壁の色分け」「主要建物への限定的な実テクスチャ」「海と狩野川の水域分離」**を採用する設計とします。

Muse（さぼてん）向けの判断として、地図は街を見分けるための実景らしさを優先し、濃紺・生成り・Shippori Minchoによる標本図鑑の印象は、UIや店舗の展示プレートで保ちます。うみまちラボ沼津が段階的に実装できるよう、テクスチャの調査結果を待たずに色分けと水域表現を進められる構成にします。

以下の容量・性能値は設計目標です。変更後の実測値ではありません。

**建物は、実際の色が確認できるものから優先して反映します。**

外観の決定順は「確認済みの個別指定 → 利用可能な実テクスチャ → 用途別の推定色 → 未分類の標準色」とします。個別指定には建物ID、屋根色、外壁色、出典、確認日を持たせます。2021年度データの外観と、現在の店舗情報による補正を区別して管理できます。

実テクスチャが使える場合は、次の範囲から採用します。

- 初期対象は、ガチャ・街めぐりの目的地となる店舗と、目印になる建物の**10〜20棟程度**。屋根と、通常のカメラから見える外壁を優先する。
- その他の建物は用途別カラーを使用。対象棟数は固定せず、画面上の効果と容量予算で調整する。
- LOD2に画像と有効なUVがあれば、その対応を維持して変換する。
- 画像がLOD3にだけ付いている場合は、LOD2へのベイクを検討する。形状対応が取れない建物はカラー表示に戻すか、重要な数棟に限ってLOD3を採用する。LOD3のUVをそのままLOD2に流用する前提にはしない。

画像が存在するだけでは採用を決めず、参照先の画像、対象面、UV、解像度、屋根だけか外壁まであるかを確認します。

圧縮・マテリアルの仕様は以下を基本とします。

| 項目 | 設計 |
|---|---|
| 画像配置 | 最大2048×2048のアトラス2枚。低負荷用に1024版も生成 |
| 面ごとの解像度 | 通常128〜512px程度を出発点に、最大ズーム時の表示面積で配分 |
| 圧縮 | KTX2／Basis Universal。ETC1Sを基本に、画質不足のページのみUASTCを比較 |
| 転送量 | 建物テクスチャ合計1.5MBを目標、2.0MBを上限 |
| 遠景対策 | ミップマップを生成。アトラス境界に余白と色の延長処理を入れる |
| 材質 | 基色は白、金属度0、粗さは高め。写真の色を活かす |
| 描画単位 | アトラス単位＋共通カラー用にまとめる。建物ごとのマテリアル生成を避ける |

現在の生成り色の頂点カラーを写真に掛けると、外観全体が黄ばんで見えます。**テクスチャ適用時は、その描画単位の頂点カラーによる着色を無効化**します。色画像はsRGBとして扱い、色空間変換の重複を確認します。

実テクスチャが使えない場合も、屋根と外壁を分けるだけで建物の形と街の用途が読み取りやすくなります。以下は実際の塗装色が不明な建物に使う、推定パレットの初期案です。

| 用途 | 外壁 | 屋根 |
|---|---|---|
| 商業・店舗 | 暖かいグレージュ `#D7C8B5` | 灰褐色 `#82776C` |
| 住宅 | 明るい灰白色 `#D9D4CA` | 濃灰色 `#646A70` |
| 倉庫・工場・港湾施設 | 青みのある灰色 `#C5CCCF` | 青灰色 `#73828B` |
| 公共・文化施設 | 生成り `#E6E0D3` | 中間灰色 `#858A89` |
| 用途不明 | 中立的な灰色 `#CFCEC8` | 灰色 `#777C7C` |

用途コードは元データのコードリストに従って対応付け、不明値は未分類にします。同じ用途でも、建物IDから決まる小さな明度差を付けて単調さを減らします。再読み込みで色が変わらない方式にします。

屋根・外壁の判定には、元データの面分類を優先します。面法線も維持し、弱い環境光と方向光で屋根の勾配を読ませます。店舗固有の色は、建物との対応と外観が確認できたものを個別指定します。

**海と狩野川は、色・流路形状・水面模様の三つで区別します。**

| 水域 | 色の初期案 | 表現 |
|---|---|---|
| 海・内港 | 深い青 `#183B52` | 大きく、低コントラストな水面模様。内港では揺らぎを弱める |
| 狩野川 | 明るめの灰緑色 `#527B78` | 流路に沿った細長い模様を、控えめに下流へ動かす |
| 河口 | 川から海へ連続変化 | 河口から川側へ約20〜40mを出発点に、海色へなじませる |

色は実測した水色ではなく、判別性を確保するための初期値です。実景との比較と実機表示で調整します。狩野川は海より明るくし、静止画でも区別できる状態を必須とします。内港は海として扱います。

水面の構造は次のとおりです。

- **狩野川の流路ポリゴンを独立して持つ。** 既に再現できている地形・水際を基準に境界を作り、不足部分だけ参照資料で補う。
- 海と川のポリゴンは、河口で境界を共有させる。海の平面が川の下まで重なる構造は、川領域を除く形に変更する。
- 海面は既存のローカルENU座標の **y=41.5** を基準とし、河口側の川面を合わせる。上流側の水面高は河道との整合を確認して設定する。
- 水域内にDEM面が残って水面を隠している場合は、その部分を水域境界で切り抜く。岸の陸地は保持し、隙間が出る箇所に必要最小限の側面を補う。
- 水面は不透明・深度書き込みありとし、軽量な共通シェーダーを海と川で使う。小さなノイズ画像のUV移動で模様を表現する。

第3弾では、反射用の別描画、屈折、透過、頂点を動かす波は対象外とします。低負荷設定では水面模様を静止させ、色と流路による判別性を維持します。

**性能は、現在の約1.0MB・126k tris・19描画コールを基準に管理します。**

容量は、現状値と比較できるよう、GLB・画像・水域データ・メタデータを合わせた「選択した画質で実際に取得する3Dアセット量」とします。高画質版と低画質版を両方ダウンロードする構成にはしません。

| 指標 | 目標 | 第3弾の上限目安 |
|---|---:|---:|
| 最初の地図表示に必要な3Dアセット | 1.3MB以内 | 1.5MB |
| テクスチャ読み込み後の3Dアセット合計 | 3.0MB以内 | 4.0MB |
| 建物テクスチャ内訳 | 1.5MB以内 | 2.0MB |
| 表示中の三角形数 | 150k以内 | 180k |
| 1フレームの描画コール | 30以内 | 40 |
| 今回追加するGPUテクスチャ使用量 | 16MiB以内 | 24MiB |
| 通常操作時のフレーム時間 | 60fpsを目標 | 実機でp95が33ms以内 |

3.0MBの配分例は、UV追加などを含む形状データ1.3MB、建物画像1.5MB、水面・メタデータ等0.15MBです。新規デコーダーのJS／WASMは別途計測し、圧縮後の転送増分0.5MB以内を目安とします。検証結果にはアプリ本体を含む総通信量も記載します。

KTX2の転送量とGPUメモリ量は別です。2048²の画像2枚がRGBA8に展開されると、ミップ込みで約42.7MiBになります。この場合は1024版を選び、同条件で約10.7MiBまで下げます。対応形式と画像サイズを基に使用量を推定し、端末に合った版を読み込みます。

超過時は、指標ごとに対処します。転送量・メモリは画像解像度と採用範囲、描画コールはバッチ統合、三角形数はLOD3採用範囲を調整します。

**Antigravity向けのデータ変換タスクは、次の単位に分けます。** ファイル名は成果物の提案です。

| ID | 作業 | 成果物・完了条件 |
|---|---|---|
| D1 | LOD2／LOD3の外観情報を監査する | `texture-audit.json`。建物ID、対象LOD、画像参照、UVの有効性、屋根／外壁の収録範囲を記録。画像なし・一部あり・利用可能を判定 |
| D2 | 用途別カラーと個別指定を適用する | 全建物に屋根色・外壁色を設定。未分類も表示可能。同じ建物IDでは毎回同じ色になる |
| D3 | 利用可能な画像を選別し、アトラス化・KTX2圧縮する | 2048版／1024版、更新したUV、画像適用先のマニフェスト。欠損面はカラー表示に接続。画像なしの場合は空のマニフェストを出力 |
| D4 | 海・川・河口の水域を作る | `water.glb`等。共有境界、河口の混合率、川の流向を保持。必要なDEM切り抜きと岸の補修を実施 |
| D5 | 描画単位をまとめ、検証情報を出力する | 建物を共通カラー／アトラス単位に統合。元の建物IDとの対応を保持。容量、tris、頂点数、材質数、画像サイズを記録 |

D3では、三角形分割後もUVの対応が保たれているか、屋根画像が壁へ回り込んでいないかを目視確認します。LOD3からのベイクは対象建物単位で扱い、他の建物の変換を止めない構成にします。

Three.js側は次のタスクに分けます。

| ID | 作業 | 完了条件 |
|---|---|---|
| T1 | カラー状態で地図を先に表示する | 建物形状にUVと代替色を保持し、最初の操作可能なフレームでは画像取得を待たない |
| T2 | マニフェストに従って画像を後から適用する | 使用中のThree.js版とKTX2Loaderの対応を確認。画像取得後に材質を切り替える。取得・復号失敗時もカラー表示を維持 |
| T3 | 建物の光と色を調整する | テクスチャの生成りへの偏り、二重の色変換、過度な陰影を解消。屋根形状と店舗の色が読み取れる |
| T4 | 海・川の水面を実装する | 水域2メッシュを基本とし、河口の色補間と川の流向を反映。ちらつき、陸へのはみ出し、水面の欠落がない |
| T5 | 低負荷設定と既存機能の接続を行う | 1024画像・静止水面を選択可能にする。既存の店舗選択等がある場合は、建物IDとの対応を維持 |
| T6 | 同条件で比較計測する | 現行版、カラー版、テクスチャ版について、通信量、描画コール、tris、フレーム時間、画像適用時の停止を記録 |

実装順は **D1・D2・D4 → D5 → T1・T3・T4 → 利用可能ならD3・T2 → T5・T6** とします。最初にカラー版と水域表現を完成させ、その上に実テクスチャを追加します。

完了判定には、全景・主要店舗の近景・狩野川河口の固定視点を使います。

- 屋根と外壁の差、主要な店舗・建物の特徴が現行版より読み取りやすい。
- 地名ラベルと水面アニメーションを止めても、海と狩野川を判別できる。
- 河口に直線的な色の切れ目やちらつきがなく、川幅と岸の形が地形に合っている。
- テクスチャが使えない場合も、完成したカラー版として成立する。
- 確認済みのスマホで読み込み後に60秒程度操作し、上限目安を満たす。初回表示と画像適用時の引っかかりも別途確認する。
