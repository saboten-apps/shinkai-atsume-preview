# 深海ガチャ × お店めぐり（仮称） MVP仕様 v0.1

決定: 2026-11-09 ユーザー決定「深海ガチャとお店系を足して2で割ったイメージでいく」
事業: うみまちラボ沼津 / 目的: Threads地域投稿のネタ生成 + 実在のお店・イベントへの集客
開発分担: GPT（素材・イラスト・設計補助・Codex実装補助） / Antigravity（実装本体） / Muse（仕様・裏取り・中継・検品・公開・運用）

## コンセプト
駿河湾の深海魚のデイリーガチャ（毎日、全員に同じ1種が出る）で「今日開く理由」と
シェア用カードを作り、カードの下半分で「会いに行く／食べに行く」実在の行き先
（当面は沼津港エリア単位、協力店がついたら店単位）へ送客する。

## 段階設計
### 段階0（MVP・交渉ゼロで公開可能）
- 1日1回ガチャ。その日の魚は日付シードで全員共通
- 魚カード: イラスト / 名前 / レア度 / 生息水深 / 一言うんちく（出典つき・裏取り済みのみ）
- 行き先欄: エリア単位のみ（沼津港エリア、深海水族館のあるエリア等）。
  「今日この店でこの魚が食べられる」式の断定は絶対にしない。
  リンクは公式ページ・Googleマップ検索へ
- 図鑑: 端末内（localStorage）にコレクション保存。コンプ率表示
- 結果カード画像の生成（Canvas）→ SNSシェア用。人生すごろくの結果カードの型を踏襲
- 1問クイズ（任意・MVPに含めるかは魚データの裏取り速度次第）
- 計測: アクセス集計のみ（個人データなし）。行き先リンクのクリック数を数える

### 段階1（協力店がついてから）
- 担当魚制: 協力店が深海魚を1種担当。来店で図鑑スタンプ（店頭QR）付与
- 合言葉 / 画面提示による来店カウントをお店に月次で返す
- お店の登録・修正は店側フォーム（運営は承認のみ）。公式Instagram・地図リンク必須

### 段階2（数字がついてから）
- イベント版（週末イベントの担当魚・特設カード）
- 収益化は副業届完了後まで打ち出さない。まずは無料掲載で実績づくり

## 画面（MVP）
1. トップ = 今日のガチャ（引くボタン、引いた後はカード表示）
2. 図鑑（グリッド、未所持はシルエット）
3. 魚詳細（カード再表示 + 行き先リンク）
4. このアプリについて（うみまちラボ沼津、免責: 魚の提供・展示は各施設の当日の状況による）

## データ
- fish.json: id / name / rarity(★1-5) / depth_m / fact / fact_source_url / area_hint / illustration_file
- 魚は24種で開始（裏取り完了したものだけ投入。未検証は入れない）
- イラスト: GPT生成、統一様式（深海の暗背景・発光アクセント・魚ごとに色コード）。
  様式プロンプトはGPT側スターター資料で確定する

## Threads運用ループ
- 毎日: 「今日の深海魚」カード画像 + 一言 + 質問締め（見たことある？食べたことある？）
- 週1: 図鑑コンプ率や珍しい魚のまとめ
- 段階1以降: 担当店が増えるたびに紹介投稿1本
- 投稿は従来どおり本人の事前確認制。リンクは本文に入れず1stリプライ

## 技術
- 静的サイト（HTML/CSS/JS or Vite）。バックエンドなし（段階0）
- 公開: まだ先（ユーザー決定 2026-11-09）。GitHubアカウント停止の控訴結果を待ってから公開方法を決める。それまでは開発・素材制作をローカルで進めるのみで、Netlify等への先行公開もしない
- 保管: 当面は Muse VM の workspace。GitHub復旧後にリポジトリを作成して移管する想定

## 英語版（検討決定 2026-11-09・外国人観光客ターゲット）
- 最初から多言語前提で設計する（後付けは高い）。UI文言は言語ファイルに分離し、日英トグルを用意
- fish.json に name_en（英語通称名）と学名を持たせる。英語通称名も日本語名と同様に裏取りしてから投入する（担当：リサーチ継続）
- 段階0の英語範囲：UI＋魚カード＋「このアプリについて」まで。お店ページは英語1行サマリ（店側確認済みのみ）
- 狙い：沼津・伊豆への訪日客（日本一深い駿河湾＋深海水族館は英語情報が薄く、検索でも差別化できる）。アプリはインストール不要のWebで、現地QRからそのまま遊べる形が観光客に合う
- お店側の訴求にもなる：「英語対応」バッジ、訪日客へのリーチを有料機能の柱の一つにする
- 英語の問い合わせ窓口は持たない（各店・施設の公式へリンク）

## ユーザーコメント機能（希望あり 2026-11-09・段階案）
- 段階0: アプリ内にコメント欄は作らない。魚カード/店舗カードから当日のThreads投稿へ誘導し、コメントはThreadsに集める（モデレーションはプラットフォーム側、Threads育成にも直結）
- リアクションボタン（採用決定 2026-11-09 ユーザー「行きたいとかのボタンならいいかもね」）: 「行きたい」「行ったよ」の2ボタンを魚カード/行き先カードに付け、人数カウントを表示する。テキスト入力なし・ログインなし。小さなバックエンド（Workers+D1想定）で実装し、枠の消費量は要監視。「行ったよ」は自己申告カウントとして扱い（来店の証明とは呼ばない）、店舗確認済み来店数とは分けて集計する。「行きたい」数はお店への関心指標として月次レポートに使える
- 段階1以降: 「ひとこと投稿＋承認制表示」（投稿→運営承認→表示）。お店への否定的コメントの事故を防ぐため、自由表示のコメント欄は作らない方針を基本とする
- フルコメント欄（ログイン制・即時表示）は運用負荷（荒らし/スパム/削除対応）が個人運営に見合わず、当面見送り
