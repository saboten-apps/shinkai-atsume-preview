沼津港周辺の3D都市空間を活用した軽量Webマップの先行技術検証（スパイク）プロジェクトです。  
スマートフォン幅（390px〜）のブラウザで軽快に動作する3D街マップ、カメラ操作（オービット・パン・ピンチズーム）、検証用仮ピン、下部情報パネル（深海生物標本連携・スタンプ体験）、リアルタイム性能HUD、および2D代替マップ（WebGL非対応時のフォールバック機能を含む）を実装しています。

**※ 本プロジェクトは `spike-3d/` フォルダ内で完全に自己完結しており、本アプリ（`../app`）への変更は一切行っていません。**

## 2. 実データ調査と仮ジオメトリ代替の理由

指示書の「データ取得の進め方」に沿って実データの検証を行いました：

1. **3D Tiles ZIPの内部探索**:
   HTTP Range Request を用いて 1.47GB の ZIP セントラルディレクトリを直接取得・解析し、`bldg_lod1/tileset.json` および沼津港境界（緯度 35.080〜35.085、経度 138.855〜138.862）に含まれるリーフタイル群（`data1760.b3dm`〜`data1917.b3dm` 等、計15タイル）を特定しました。
2. **b3dmバイナリの解析結果**:
   特定した b3dm ファイルを抽出・パースしたところ、以下の技術的制約が判明しました：
   - **メッシュ圧縮**: 内部の glTF 2.0 に `KHR_draco_mesh_compression` が適用されており、Draco デコーダー（WASM/Worker）のランタイム展開が必須。
   - **座標系（ECEF）**: `CESIUM_RTC` 拡張により、地球中心直交座標系（ECEF: EPSG:4978: `[-3935020.7, 3437832.7, 3645354.9]`）を基準として格納されている。
   - **HLODツリーの依存**: ルートノードから階層的に Geometric Error に基づいて描画される仕様のため、末端タイルのみを抜き出してローカル配置した場合、Three.js の通常のデカルト座標系（Y-up / Z-forward）との不整合、地球曲率による傾き、カメラ回転軸の破綻が生じる。
3. **CityGMLからの変換**:
   CityGML（1.21GB）からのOBJ/glTF抽出・変換には FME / QGIS / PLATEAU GIS Converter などの外部デスクトップGIS環境が必要であり、Webフロントエンド開発環境内での自動ビルド・変換は困難。

上記を踏まえ、**指示書「3. 取得が困難・過大な場合は、CityGMLからの変換も試し、それも無理なら手続き生成の仮ジオメトリ（港・海・狩野川・市街ブロックのミニチュア）で代替し、READMEに理由と実データ化の残手順を書く。検証の主眼（描画・操作・ピン・パネル・性能表示）は仮ジオメトリでも成立させる」** の規定に基づき、**手続き生成による沼津港仮ジオメトリ（標本ミニチュア模型風ローポリジオメトリ）** で代替実装しました。

### 実データ化に向けた残手順
今後、PLATEAU実データを本番投入する際の推奨パイプラインは以下のとおりです：

1. **メッシュ切り出しとOBJ/glTF変換**:
   PLATEAU GIS Converter（またはFME/QGIS）を用い、沼津港該当メッシュ（`5238-4698`, `5238-4699`）の建築物（bldg LOD1またはLOD2）および道路・地形データをローカル平面直角座標系（日本測量系系番号VIII系: EPSG:6676）に投影変換して glTF / OBJ としてエクスポートする。
2. **ローカル原点設定（ENU化）**:
   沼津港中央（例: びゅうお付近 緯度35.0815, 経度138.8576）を (0, 0, 0) としたローカルENU座標に平行移動し、Y-up座標系へ整合させる。
3. **Draco / Meshopt 最適化と軽量化**:
   `gltf-pipeline` または `gltfpack` を用いて重複頂点の統合、不要アトリビュート削除、テクスチャのWebP/KTX2化を行い、ファイルサイズを数百KB〜数MBに圧縮する。
4. **Three.js GLTFLoader への差し替え**:
   `src/three/sceneBuilder.ts` 内の手続き生成メッシュ部分を、最適化済み `.glb` の読み込み処理（`GLTFLoader` + `DRACOLoader`）に置き換える。

  - 千本松原（海岸沿いの松林）
  - PLATEAU LOD1風の周辺市街地ブロック群（端正な墨色エッジライン付き）
  - 係留漁船、白灯台・赤灯台
- **カメラ操作（OrbitControls）**:
  - 1本指ドラッグ: 自由オービット回転（地表潜り込み防止のリミット付き）
  - 2本指操作: パン（平行移動）およびピンチイン・ピンチアウト（ズーム）
  - 初期視点: 沼津港を斜め上空から見下ろすバードビュー構図
  - スマホ幅（390px）に最適化
- **3Dピンマーカー & レイキャスティング**:
  - 標本針と真鍮を模したピン、光環（Halo）の波紋アニメーション
  - タップ／クリック検出（Raycaster）、ドラッグ操作と誤判定しない距離・時間しきい値判定
  - 選択中ピンへのスムーズなカメラ注視フォーカス

  - タップすると押印状態が切り替わり、localStorageに永続化される体験機能。

### 3) 性能表示（PERF HUD）
- 画面左上に小さく常時表示：
  - **FPS**: リアルタイム計測フレームレート（30fps未満で警告色）
  - **Calls**: レンダラー描画コール数（Draw Calls）
  - **Tris**: 描画三角形ポリゴン数
  - **DPR**: Device Pixel Ratio（指示書要件に基づき上限2に制限: `Math.min(window.devicePixelRatio, 2)`）

### 4) 2D代替マップ & WebGL非対応フォールバック
- ヘッダーの「3D」「2D」トグルボタンで即座に切り替え可能。
- 沼津港の標本地図風SVGマップ（海、川、びゅうお、魚市場、松原、ピン位置）。
- 5地点のピン一覧カード群（カードタップで該当ピンの詳細パネルが開く）。
- **WebGL非対応環境の自動検出**:
  `WebGLRenderingContext` の利用可否を判定し、非対応時は自動で2D表示に切り替え、「※お使いの環境ではWebGLが利用できないため、2Dマップを表示しています」というバナーを表示。

### 5) 標本図鑑トーンのデザイン
- カラー: 濃紺（`#0B1C2C`, `#07131E`, `#102437`）と生成り（`#F5F0E6`, `#ECE5D5`）を基調とし、アクセントに深海レッド（`#C73E2C`）を使用。

## 8. PLATEAU実データ統合（2026-11-12実施）

先行テスト（`../realdata-test/RESULT.md`）で抽出・最適化したPLATEAU実データ（沼津港周辺）を、本スパイク（`spike-3d`）へ正式統合しました。  
従来の手続き生成による仮ジオメトリから、実測ENU座標系に基づく実建築物・道路モデルへの置き換えを完了し、スマートフォンでも軽快に描画・操作できることを実証しています。

### 1) 採用データ・ファイルサイズ・ポリゴン数

`public/data/` に以下の最適化済みglTF（GLB）を配置して読み込んでいます：

| データ種別 | ファイル名 | ファイル容量 | タイル数 / 棟数 | 三角形ポリゴン数 | 形式・圧縮 |
|---|---|---|---|---|---|
| **建築物 LOD2（clean版）** | `port-bldg-lod2-clean-packed.glb` | **414,680 B**（約405 KB） | 43タイル / 525棟 | **59,112** | 屋根形状あり、建物ごとの明度変調頂点カラー（COLOR_0）、gltfpack（meshopt） |
| **道路 LOD3** | `port-road-packed.glb` | **19,940 B**（約20 KB） | 13タイル | **3,688** | 港〜駅コリドー区間、gltfpack（meshopt） |
| **合計** | - | **434,620 B**（**約425 KB**） | - | **62,800**（約62.8k） | - |

- **軽量性の実証**: 沼津港周辺の全建築物LOD2＋道路LOD3を含めても**合計約425 KB**に収まり、三角形数も**約62.8k**と、モバイル向けWebGLの目標値（100k〜200k未満）を大幅に下回る軽快な描画負荷を達成しています。
- **clean版の採用**: 初期版GLBに存在したglTF Y-up軸マッピングの不整合（ECEFオフセットの未変換）を修正し、港湾地区の基礎高さを地表面 **y ≈ +41.7 m**（楕円体高）に完全整合させた clean 版を使用しています。

### 2) 座標系と土台平面

- **ローカルENU座標系**: 原点 = 沼津港（緯度 35.0815、経度 138.8576、楕円体高 0）、軸 = `x: 東`, `y: 上`, `z: −北`（右手系・単位メートル）。
- **地形の代替**: 配布ZIP内に地形テーマ（dem）が存在しないため、指示書仕様に基づき2枚の土台平面で代替しています：
  - **陸の土台**: 生成りサンド（`#D7CFBE`、roughness 1.0、2400×2400 m）を建物の基礎直下 **y = 41.45** に配置。
  - **海面**: 従来の濃紺（`#071B2D`、roughness 0.25、2400×2400 m）を陸より少し低い **y = 41.15** に配置。陸の土台南端から手前の駿河湾（濃紺）が露出し、港湾の岸壁段差（0.3m）を標本風に表現。

### 3) マテリアルと標本図鑑トーンの表現

- **建物（LOD2）**: `MeshStandardMaterial`、`vertexColors: true`、`roughness: 0.85`。元データの `COLOR_0` に焼き込まれた、ベース色 `#EEE8DC` に対する建物ごとのHSL明度変調（±6%）を反映し、同一色で潰れずに建物の立体感・輪郭が際立つ標本模型トーンを実現。
- **道路（LOD3）**: `MeshStandardMaterial`、スレートグレー（`#3D4B53`）、`roughness: 0.9`。
- **非同期ローダー**: Three.js の `GLTFLoader` に `MeshoptDecoder` を組み込み、読み込み完了までの間、画面右上に標本調の「PLATEAU実データを読み込み中…」スピナーを表示。

### 4) カメラ・操作範囲の拡張

対象地理範囲が約850m四方に拡大したことに合わせ、カメラとフォグのパラメータを調整：

- **カメラ初期位置**: `(390, 350, 430)`（駿河湾上空の南東側から港を見下ろす構図）
- **カメラ注視点**: `(0, 43, -80)`（港北側の市街地中心、地面高さ y ≈ 41.7 付近）
- **操作制限（OrbitControls）**: `minDistance: 40`、`maxDistance: 1400`、`maxPolarAngle: Math.PI / 2 - 0.05`
- **フォグ（FogExp2）**: 濃度を `0.0008` に調整し、850m四方の都市空間全体が深海ネイビーの空間に見通せるよう調整。
- **カメラ描画深度**: `far` を 5000 に拡大。

### 3) 海と狩野川の水域分離・配置仕様

   - それ以外の小ポリゴンは、ENU重心 $x > 100$ を「狩野川（river）」、それ以外を「海・内港（sea）」に判定。
2. **河口部の色補間（グラデーション）**:
   - 海ポリゴン: 一様な深海ブルー `#183B52`。
   - 川ポリゴン: 河口合流点 `(219, -411)` からの距離 40m 以内において、海色 `#183B52` から狩野川の明るい灰緑色 `#527B78` へとなめらかにブレンド。40m 以遠の上流側は完全な `#527B78`。
3. **高さオフセットと重ね合わせ**:
   - 全面の海平面（2400×2400m）: 色を `#183B52` に更新し、**y = 41.5** に配置。

### 4) 水面の質感づけ（自前ノイズテクスチャとUVアニメーション）

1. **シームレス・低コントラストなノイズテクスチャの自前生成**:
   - 外部画像ファイルをロードせず、コード内で 128×128 ピクセルの `THREE.DataTexture` を自前生成（GPU転送量わずか 64KB）。
   - 8系統の整数周波数サイン波を干渉合成し、テクスチャ境界（u=0/1, v=0/1）で数学的に完全に連続・シームレスなラップアラウンドを実現。
   - 粗さ（roughness）のレンジを 0.25 〜 0.55 の低コントラストに正規化し、水面マテリアル（海・川）の `roughnessMap` として適用。ベースの頂点カラー（色判別）を一切阻害せず、太陽光・環境光のスペキュラハイライトの微細なさざ波のみを表現。
2. **ワールドENU座標に基づくUV生成**:
   - 元の MVT 水面GLBには UV（`TEXCOORD_0`）が含まれないため、ロード時にワールド ENU 座標 $(x, z)$ からスケール `0.04`（約25m周期）でシームレスな UV を自動生成。
3. **レンダーループでの流動スクロール**:
   - **海**: 極低速（$\Delta x: +0.003/\text{s}, \Delta y: +0.002/\text{s}$）で斜めに緩やかに揺らぎ、潮のうねりを表現。
   - **川**: 下流方向（北＝−z側へ流れる向き）へ低速（$\Delta y: +0.025/\text{s}$）でスクロール。南から北の駿河湾へと注ぎ込む狩野川の自然な水流を再現。
   - 静止画やアニメーション停止時でも、色分け（#183B52 vs #527B78）と流路形状により海と川が明確に判別可能です。

### 2) ヒーロー（目印建物）選定ルール

港の空間認識性向上とデータ容量の最適バランスを図るため、以下のルールで49棟を選定しました：

1. **ランドマーク近傍条件**:
   - 港の主要目印3地点（びゅうお `(-210, -366)`、深海水族館 `(-73, -300)`、魚市場 `(-36, -233)`、ENU座標）のいずれかから、建物重心（全頂点のXZ平均）が **60m 以内** に位置する建物（40棟）。
2. **フットプリント規模条件**:
   - 港 bbox 内の底面フットプリント投影面積（幾何法線 $n_y < -0.5$ の XZ 投影面積）の **上位10棟**（うち1棟は魚市場近傍条件と重複したため新規は9棟）。
3. **選定結果**:
   - 重複排除後、合計 **49棟**（49棟すべてが元データに利用可能な写真テクスチャを保有）。
   - 初回構築で容量予算（packed 約2.2MB）を大きく下回る約1.27MBに収まったため、予算超過による切り捨て（ドロップ）は0件で全49棟を収録。

### 3) 遅延ロード方式とライフサイクル

初期表示の即時性と実写テクスチャの表現力を両立するため、2段階のロードシーケンスを実装しました：

1. **初期表示フェーズ（初期総容量 約0.99 MB）**:
   - カラー版建物（nohero: 370KB）＋ 道路（20KB）＋ 地形（508KB）＋ 植生（68KB）＋ 海水面（7KB）＋ 川水面（7KB）の計6種を並行ロード。
   - **初期ロード総容量**: **993,032 B**（**約0.99 MB** / 970 KB）。1MB未満を達成し、第3弾（1.05MB）よりも初期描画待機時間を短縮。
   - ロード完了と同時に街並み・水面・地形・ピンの3D描画が開始され、ユーザーは即座に操作可能。
2. **実テクスチャ遅延ロードフェーズ（テクスチャ適用後総容量 約2.26 MB）**:
   - 初回レンダリングの安定後、`requestIdleCallback`（フォールバック: 300msタイマー）によりブラウザのアイドル時間を利用してバックグラウンドで `port-bldg-hero-tex-packed.glb` を非同期読み込み。
   - ロード完了次第、シーンに追加（目印建物49棟の実写真テクスチャが出現）。
   - **テクスチャ適用後総容量**: **2,259,884 B**（**約2.26 MB** / 2,207 KB）。設計仕様書の上限目安（テクスチャ読み込み後 4.0MB）に対して十分な安全マージンを確保。
3. **耐障害性（フォールバック保証）**:
   - 通信遅延やエラー等でテクスチャ版のロードに失敗した場合でも、例外でレンダーループを落とさず `console.warn` でハンドリング。画面クラッシュを起こさず、カラー版（476棟）の表示のまま安定して利用を継続可能。
   - コンポーネント破棄時には遅延ロードタイマー・アイドルコールバックを安全にキャンセルし、テクスチャ（15枚）・ジオメトリ・マテリアルをリークなく破棄。

### 4) マテリアル仕様と描画負荷（ドローコール）

1. **実テクスチャとカラーのそのままの活用**:
   - ヒーロー版のマテリアルにはGLB内蔵のWebPテクスチャおよびUVトランスフォーム（KHR_texture_transform）をそのまま適用。
   - 生成りティントの上書きを行わず、テクスチャ面は実写本来の発色を維持。無テクスチャ面（屋根等）は元データの中立グレー（0.8, 0.8, 0.8）頂点カラーで端正に表示。
2. **描画コール（Draw calls）の目標達成**:
   - ヒーロー版GLBは単一メッシュ内に16個のプリミティブ（テクスチャ15種＋無テクスチャ1種）で統合。
   - ドローコール増加はわずか +16 回に抑えられ、**合計描画コールは約37**（第4弾目標の「40以内」を達成）。
   - 合計三角形数は約126k（第3弾と同一）。
